# Public Project Preparation

## Goal

Prepare the repository for public GitHub publication without live secrets or production backup archives.

## Decisions

- Keep Bash and fish as the implementation and operator interface.
- Separate reads (`backup`, `validate`) from writes (`bootstrap`, `deploy`, `restore`, `activate`).
- Require `DEPLOY_CONFIRM=YES` for server-changing commands.
- Use `.env.example` as the public operator configuration contract.
- Keep backup archives and private environment files out of Git.
- Use a dedicated rootless Podman service account for containers; keep host services under systemd.
- Treat Portainer's rootless Podman support as best-effort until the upstream support matrix changes.

## Limits

Bootstrap targets Debian/Ubuntu with systemd. SSH, DNS, TLS, firewall rules, application-specific workloads, and application-data backups remain separate reviewed operations.
